# Лабораторная работа № 3: Базовые растровые алгоритмы

**Тема:** Реализация и анализ алгоритмов растеризации отрезков и окружностей на Java.

## Описание проекта
Приложение с графическим интерфейсом (Swing), визуализирующее работу фундаментальных алгоритмов компьютерной графики. Программа позволяет строить линии, сглаженные линии для демонстрации работы с прозрачностью и окружности на дискретной сетке, масштабировать область просмотра и замерять время выполнения алгоритмов.

### Реализованные алгоритмы:
1.  **Пошаговый алгоритм** (Step-by-step)
2.  **Алгоритм ЦДА** (DDA — Digital Differential Analyzer)
3.  **Алгоритм Брезенхема для отрезков** (Bresenham's Line Algorithm)
4.  **Алгоритм Брезенхема для окружностей** (Bresenham's Circle Algorithm)
5.  **Алгоритм Кастла-Питвея** (Castle-Pitteway) — целочисленный алгоритм генерации сглаженных линий.

## Особенности реализации

### Система координат
*   Центр окна — логическое начало координат `(0, 0)`.
*   Ось **Y** направлена **вверх**, ось **X** — **вправо**.
*   Координатная сетка поддерживает масштабирование (Zoom) колесиком мыши.
*   Преобразование логических координат в экранные (`cellSize` — размер клетки в пикселях):

$$ Screen_X = Center_X + (Logic_X \cdot cellSize) $$
$$ Screen_Y = Center_Y - (Logic_Y \cdot cellSize) - cellSize $$

### Визуализация сглаживания
Для алгоритма Кастла-Питвея реализована поддержка **альфа-канала** (прозрачности). Вместо бинарного закрашивания (черный/белый), пиксель может иметь интенсивность от `0.0` до `1.0`. Визуально это отображается через изменение прозрачности синего цвета.

## Теоретическая справка и проверка

Для проверки корректности проведен ручной расчет построения отрезка **(0, 0) → (5, 2)**.
*Дано:* `dx = 5`, `dy = 2`.

### 1. Алгоритм ЦДА (DDA)
*Принцип:* Использование вещественных приращений.
`Steps = 5`, `incX = 1`, `incY = 0.4`.

| Шаг (i) | X (float) | Y (float) | Округление (int) | Результат программы |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 0.0 | 0.0 | **(0, 0)** | ✅ Совпадает |
| 1 | 1.0 | 0.4 | **(1, 0)** | ✅ Совпадает |
| 2 | 2.0 | 0.8 | **(2, 1)** | ✅ Совпадает |
| 3 | 3.0 | 1.2 | **(3, 1)** | ✅ Совпадает |
| 4 | 4.0 | 1.6 | **(4, 2)** | ✅ Совпадает |
| 5 | 5.0 | 2.0 | **(5, 2)** | ✅ Совпадает |

### 2. Алгоритм Брезенхема (Line)
*Принцип:* Только целочисленная арифметика. Анализ ошибки `E`.
`E_start = 2*dy - dx = -1`.

| Шаг | Текущая (x, y) | Ошибка (E) | Действие | Новый E |
| :--- | :--- | :--- | :--- | :--- |
| 0 | **(0, 0)** | -1 (<0) | `x++` | -1 + 4 = 3 |
| 1 | **(1, 0)** | 3 (>=0) | `x++, y++` | 3 - 6 = -3 |
| 2 | **(2, 1)** | -3 (<0) | `x++` | -3 + 4 = 1 |
| 3 | **(3, 1)** | 1 (>=0) | `x++, y++` | 1 - 6 = -5 |
| 4 | **(4, 2)** | -5 (<0) | `x++` | -5 + 4 = -1 |
| 5 | **(5, 2)** | — | Конец | — |

### 3. Алгоритм Кастла-Питвея (Сглаживание)
*Принцип:* Распределение интенсивности (100%) между двумя соседними пикселями в зависимости от смещения идеальной линии.
*Наклон:* $k = 0.4$.

| Шаг X | Идеальный Y | Основной пиксель | Интенсивность | Соседний пиксель | Интенсивность | Сумма |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 0.4 | **(1, 0)** | $1 - 0.4 = \mathbf{0.6}$ | **(1, 1)** | $\mathbf{0.4}$ | 1.0 ✅ |
| 2 | 0.8 | **(2, 1)** | $0.8$ (ближе к 1) | **(2, 0)** | $0.2$ | 1.0 ✅ |
| 3 | 1.2 | **(3, 1)** | $0.8$ (ближе к 1) | **(3, 2)** | $0.2$ | 1.0 ✅ |

*Проверка показала, что программа корректно распределяет интенсивность, создавая визуальный эффект гладкой линии.*

### Анализ вычислительной эффективности

1.  **Нагрузка на конвейер (Pipeline):**
    *   **Пошаговый метод** сильно нагружает блок FPU (Floating Point Unit) и требует дорогих вызовов функций стандартной библиотеки, что дает худший результат.
    *   **Брезенхем** идеален для конвейера: отсутствие зависимостей от данных с плавающей точкой и предсказуемые ветвления позволяют процессору выполнять инструкции суперскалярно.

2.  **Проблема алгоритма Кастла-Питвея:**
    Несмотря на теоретическое снижение сложности цикла до $O(L/2)$, реальная производительность страдает из-за **Branch Misprediction Penalty**. Современные процессоры пытаются предугадать следующую инструкцию. Хаотичные переходы внутри "сложного ветвления" этого алгоритма сбрасывают конвейер, заставляя CPU тратить такты впустую, что делает его медленнее простого Брезенхема на современных архитектурах x86/x64.

### Выводы по производительности

1. **Алгоритм Брезенхема** показал наилучший результат (~195 мс). Использование исключительно целочисленной арифметики позволяет задействовать самые быстрые инструкции процессора (ALU) без обращения к блоку плавающей точки (FPU).
2. **Алгоритм ЦДА** (~393 мс) отстает примерно в 2 раза из-за накладных расходов на работу с типом `float` и постоянного приведения типов при отрисовке пикселей.
3. **Пошаговый алгоритм** (~1287 мс) является абсолютно неэффективным для реальных задач из-за тяжелых операций деления и округления на каждой итерации.
4. **Алгоритм Кастла-Питвея** (~380 мс) в данной реализации оказался сопоставим с ЦДА и медленнее Брезенхема. Это связано с тем, что сложная логика ветвления внутри цикла мешает работе конвейера современных процессоров (Branch Prediction), нивелируя выгоду от уменьшения количества итераций.

## Структура кода

*   `RasterAlgorithmsApp` — Главный класс, сборка окна, UI.
*   `RasterAlgorithms` — Статический класс, содержащий математическую реализацию 5 алгоритмов.
